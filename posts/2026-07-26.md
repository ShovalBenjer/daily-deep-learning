### discounted return: חישוב אחורה

נניח trajectory קצרה: \(r_0 = 2,\; r_1 = 1,\; r_2 = 3\) עם \(\gamma = 0.9\).

חישוב **קדימה** (ישיר לפי הגדרה):

\[G_0 = 2 + 0.9 \cdot 1 + 0.81 \cdot 3 = 5.33\]

חישוב **אחורה** (מה שקוד בפועל מריץ):

\[G_2 = 3,\quad G_1 = 1 + 0.9 \cdot 3 = 3.7,\quad G_0 = 2 + 0.9 \cdot 3.7 = 5.33\]

שני הדרכים מייצרות את אותה תשובה. החישוב אחורה מועדף בקוד: לולאה אחת O(n), אין סיכום טור אינסופי, אין בעיית עצירה.

**שגיאה נפוצה**: לחשב \(G_0 = r_0 + r_1 + r_2 = 6\) ללא הנחה. זה נכון רק עבור \(\gamma = 1\), שבפועל לא נמצא בשימוש בסביבות אינסופיות.

### Advantage: מדידת עודף ביחס לממוצע

שלוש פונקציות קשורות:

\[V^\pi(s) = \mathbb{E}_\pi\!\left[G_t \mid s_t = s\right]\]

\[Q^\pi(s,a) = \mathbb{E}_\pi\!\left[G_t \mid s_t = s,\; a_t = a\right]\]

\[A^\pi(s,a) = Q^\pi(s,a) - V^\pi(s)\]

- \(A > 0\): פעולה \(a\) עדיפה על מה שהמדיניות הייתה בוחרת בממוצע.
- \(A < 0\): פעולה גרועה מהממוצע.
- \(\mathbb{E}_{a \sim \pi}[A^\pi(s,a)] = 0\) תמיד. זו הסיבה שניתן להשתמש ב-\(V(s)\) כ-baseline ב-REINFORCE ללא הטיה.

## תרגול: Binary Search - חיפוש ב-O(log n)

### המסגרת

מערך ממוין. שאלה: האם target קיים, ואיפה? חיפוש לינארי הוא O(n). binary search הוא O(log n) - בכל שלב חוצים את מרחב החיפוש לחצי.

**Invariant**: כל עוד `left <= right`, אם target קיים ב-arr הוא נמצא ב-`arr[left..right]`.

```python
def binary_search(arr: list[int], target: int) -> int:
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

שימוש ב-`left + (right - left) // 2` (ולא `(left + right) // 2`) מגן מ-integer overflow בשפות עם bounded integers. בפייתון זה לא משנה, אך כדאי להרגיל את האצבעות.

## AI-103: Generative AI ו-Agentic - גשר לשבוע 2

### RAG: Retrieval-Augmented Generation

RAG solves the problem of LLMs with stale or limited knowledge. At inference time: retrieve relevant context and inject it into the prompt.

**Flow**: user query → embed query → vector similarity search in Azure AI Search → retrieve top-k chunks → build grounded prompt → generate answer with citations.

**When to prefer RAG over fine-tuning**:
- Knowledge changes frequently (product catalog, support KB, live data)
- Citations and grounding are required
- Data is too large or sensitive to include in training

In Azure AI Foundry: AI Search provides the vector index with semantic ranking; the Agent service handles orchestration and tool calls.

### Azure AI Agent Service: Tools

An agent consists of: a model deployment, a thread (conversation history per session), and one or more tools. A Run is one execution of the agent on a thread.

**Built-in tool types**:
- `file_search` - files uploaded directly to the agent
- `code_interpreter` - runs Python in a sandbox
- `azure_ai_search` - queries an existing AI Search index
- `function` - custom function definitions (schema + handler)

## שיקול דעת: Error Budget כמדיניות פריסה

### הכלל: SRE

SLO (Service Level Objective) של 99.9% availability שווה ל-~43 דקות downtime מותר בחודש. ה-error budget הוא מה שנשאר מאותן 43 דקות.

**הכלל**: error budget הוא מדיניות פריסה, לא dashboard לניטור. budget מלא = הצוות יכול להאיץ פריסות. budget אזל = הקפאת פריסות עד לאיפוס החודשי.

הסיבה לכלל: כל deployment מוסיף סיכון. כשה-budget אזל, הסיכון הצבור גבוה מדי. לא מורידים SLO כדי לפתח בעיה תפעולית - זה משנה את הסכם עם המשתמש.
