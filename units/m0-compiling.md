# מהי קומפילציה

גם Python וגם TypeScript עוברים קומפילציה. השאלה שמבדילה ביניהם היא לא האם, אלא מה נבדק לפני שרצים ומה נשאר בקוד שרץ בפועל.

## מה תדע בסוף

להסביר מה קורה לקוד שלך בין הרגע שכתבת אותו לרגע שהוא רץ, למה `.pyc` אינו קובץ הרצה, ולמה קובץ TypeScript עם שגיאת טיפוס ברורה יכול להתקמפל בהצלחה מלאה.

## האינטואיציה

מתכון שצריך להגיע למטבח.

**קומפילציה מלאה מראש**, כמו ב-C או Rust: מתרגמים את המתכון עד הסוף לתנועות המדויקות של מטבח אחד ספציפי, לפני שמישהו נגע בסיר. אם המתכון אומר להוסיף מלח לקערת הסוכר וזה בלתי אפשרי במטבח הזה, מגלים את זה בזמן התרגום. התוצר מדבר את שפת המטבח הזה בלבד.

**קומפילציה לקוד ביניים**, כמו ב-Python: מתרגמים את המתכון לקצרנות אחידה, וטבח אוניברסלי קורא את הקצרנות שורה אחר שורה תוך כדי בישול. התרגום בודק שהמתכון כתוב בדקדוק תקין. הוא לא בודק שהוראה מסוימת הגיונית.

**הערות בשוליים**, כמו הטיפוסים ב-TypeScript: הן נכתבו בשביל הקורא. המטבח לעולם לא רואה אותן. יש מגיה נפרד שקורא את השוליים, והמתרגם פשוט מוחק אותן.

שלושת המקרים נקראים "קומפילציה". הם עושים שלושה דברים שונים.

## ההגדרות המדויקות

**Compilation, קומפילציה**: תרגום קוד מייצוג אחד לייצוג אחר לפני ההרצה. היעד אינו חייב להיות שפת מכונה.

**Machine code, קוד מכונה**: הוראות שהמעבד מבצע ישירות. זה היעד ב-C וב-Rust, ולא ב-Python וב-TypeScript.

**Bytecode, קוד ביניים**: הוראות קומפקטיות בשביל מכונה וירטואלית ולא בשביל מעבד. Python מייצר אותן ושומר אותן ב-`__pycache__/*.pyc`.

**Interpreter, מפרש** או **VM, מכונה וירטואלית**: התוכנית שקוראת bytecode ומבצעת אותו. `python` הוא זה.

**Constant folding, קיפול קבועים**: אופטימיזציה שמחשבת בזמן קומפילציה ביטוי שערכו ידוע מראש, כדי שלא יחושב שוב בכל הרצה.

**Type erasure, מחיקת טיפוסים**: הטיפוסים של TypeScript קיימים רק בקוד המקור. הכלי שמייצר את ה-JavaScript מוחק אותם, ולא נשאר מהם דבר בזמן ריצה.

**Transpile מול typecheck**: שתי פעולות נפרדות שקל להחליף ביניהן. Transpile מתרגם TypeScript ל-JavaScript. Typecheck בודק שהטיפוסים מסתדרים. `tsc` יכול לעשות את שניהם; bundler מהיר כמו esbuild או `bun build` עושה רק את הראשון.

## דוגמה מחושבת

**Python: מה באמת נוצר.**

```
python -c "import dis; dis.dis(compile('x = 1 + 2', '<s>', 'exec'))"
```

```
  0           0 RESUME                   0
  1           2 LOAD_CONST               0 (3)
              4 STORE_NAME               0 (x)
              6 LOAD_CONST               1 (None)
              8 RETURN_VALUE
```

שים לב ל-`LOAD_CONST 0 (3)`. הכתוב במקור היה `1 + 2`, אבל בקוד הביניים אין חיבור בכלל, יש את המספר 3. זהו constant folding: החישוב נעשה פעם אחת בזמן הקומפילציה.

והקובץ שנשאר:

```
python -m compileall -q m.py && ls __pycache__
```

```
m.cpython-311.pyc
```

שמונת הבתים הראשונים שלו הם `a70d0d0a00000000`. זה magic number שמזהה את גרסת ה-bytecode, ולכן `.pyc` שנוצר ב-3.11 לא ייקרא בגרסה אחרת. זה אינו קובץ הרצה: בלי `python` הוא חסר משמעות.

**TypeScript: מה שורד את התרגום.**

```
cat t.ts
```

```
function add(a: number, b: number): number {
  return a + b;
}
console.log(add(2, 3));
```

```
bun build t.ts
```

```
// t.ts
function add(a, b) {
  return a + b;
}
console.log(add(2, 3));
```

כל הטיפוסים נעלמו. מה שרץ בדפדפן הוא JavaScript רגיל שאינו יודע דבר על `number`.

**ולמה זה משנה:**

```
python -m py_compile bad.py; echo "exit=$?"
```

כאשר `bad.py` מכיל `print(add(2, "3"))`:

```
exit=0
```

הקומפילציה הצליחה. רק בהרצה:

```
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

הקומפילציה של Python בדקה דקדוק, לא משמעות.

## המקרה שמפיל את האינטואיציה

האינטואיציה אומרת: ב-TypeScript יש טיפוסים, אז הבנייה תתפוס שגיאת טיפוס. בוא נבדוק על קובץ עם שגיאה בוטה, `add(2, "3")` כשהחתימה דורשת שני מספרים:

```
bun build badt.ts
```

```
// badt.ts
function add(a, b) {
  return a + b;
}
console.log(add(2, "3"));
```

קוד יציאה 0. הבנייה הצליחה במלואה ופלטה קוד עם השגיאה בפנים.

`bun build` הוא bundler. הוא **מוחק** טיפוסים, הוא לא **בודק** אותם. בדיקת הטיפוסים היא כלי אחר לגמרי, `tsc --noEmit`, ואם אף אחד לא מריץ אותו ב-CI, הטיפוסים שכתבת הם תיעוד בלבד.

זו הסיבה שבפרויקטים אמיתיים מריצים שני דברים ולא אחד: אחד שבונה, ואחד שבודק. פרויקט שמריץ רק את הראשון ומאמין שהוא מוגן, אינו מוגן.

## טעויות נפוצות

1. **"Python היא שפה מפורשת ולכן אין בה קומפילציה"**. יש. היא מקמפלת ל-bytecode בכל הרצה, ושומרת אותו ב-`.pyc` כדי לא לחזור על העבודה. ההבדל מ-C הוא היעד, לא קיום השלב.

2. **"`.pyc` הוא קובץ הרצה, אז אפשר לשלוח אותו במקום המקור"**. הוא bytecode שדורש `python` בגרסה תואמת. הוא גם לא הסתרה של הקוד: הוא ניתן לפירוק חזרה בקלות.

3. **"אם זה התקמפל, הטיפוסים בסדר"**. תלוי מה רץ. `tsc` בודק, bundler לא. במדידה למעלה `bun build` פלט בהצלחה קוד עם שגיאת טיפוס גלויה.

4. **"שגיאת קומפילציה ושגיאת ריצה זה עניין של חומרה"**. זה עניין של **מתי**. שגיאת קומפילציה נתפסת לפני שמשתמש ראה משהו. שגיאת ריצה נתפסת כשהיא כבר קורית, ולפעמים רק בנתיב קוד נדיר שאף אחד לא הריץ בבדיקות.

5. **"קומפילציה הופכת קוד למהיר"**. לפעמים. constant folding למעלה באמת חסך חישוב, אבל הרווח הגדול בשפות מקומפלות מגיע מכך שהמעבד מריץ הוראות ישירות במקום שמפרש יקרא אותן. `.pyc` חוסך את זמן התרגום, לא את זמן הפירוש.

## מתי זה לא משנה

בסקריפט קצר שאתה מריץ בעצמך, ההבדל בלתי מורגש: תריץ, ואם משהו שבור תראה את זה מיד. ההבדל מתחיל לעלות כסף בשני מקומות. הראשון, קוד שרץ אצל אחרים, שם שגיאת ריצה בנתיב נדיר מתגלה על ידי משתמש ולא על ידך. השני, בסיס קוד גדול, שם בדיקה שרצה בשלוש שניות לפני הבנייה מחליפה שעה של חיפוש.

בראיון, השאלה "האם Python מקומפלת" היא מלכודת. התשובה הנכונה מבחינה בין שלב הקומפילציה, היעד שלו, ומה נבדק בו.
