# נתיבים במערכת הקבצים

`./data.csv` ו-`/data.csv` נבדלים בתו אחד, ומצביעים על שני קבצים שונים לגמרי.

## מה תדע בסוף

לקרוא כל נתיב ולומר מיד לאיזה קובץ הוא מצביע, בלי להריץ שום דבר; להסביר למה אותו נתיב יחסי מוצא קובץ אחר בכל פעם שמשנים תיקייה; ולזהות את המקרים שבהם כלי מתרגם נתיב מאחורי הגב שלך.

## האינטואיציה

חשוב על נתיב כעל הוראות הגעה לבניין.

יש שתי דרכים למסור אותן. אפשר למסור כתובת מלאה, "רחוב הרצל 5, תל אביב", ואז לא משנה איפה השומע עומד כרגע, ההוראות מובילות תמיד לאותו מקום. ואפשר למסור "שני רחובות ימינה ואז הבניין השני", וזה עובד רק אם השומע עומד בדיוק בנקודה שממנה חשבת. אותן הוראות בדיוק, שנמסרות למישהו שעומד בעיר אחרת, יובילו לבניין אחר לגמרי, והוא לא יקבל שום הודעת שגיאה. הוא פשוט יגיע למקום הלא נכון.

זה כל ההבדל בין נתיב מוחלט לנתיב יחסי, וזה גם מקור כמעט כל תקלת הנתיבים שתפגוש.

## ההגדרות המדויקות

**Path, נתיב**: מחרוזת שמזהה מיקום בעץ הקבצים. היא בנויה משמות של רכיבים, מופרדים בתו מפריד.

**Path separator, תו מפריד**: `/` במערכות POSIX (Linux, macOS). ב-Windows המפריד המקורי הוא `\`, אבל כמעט כל ה-API של Windows מקבל גם `/`. בתוך קוד Python או Node אין צורך לבחור ידנית: `os.path.join` ו-`pathlib.Path` ב-Python, ו-`path.join` ב-Node, בונים את המפריד הנכון לפלטפורמה.

**Absolute path, נתיב מוחלט**: נתיב שמתחיל מהשורש ולכן מזהה קובץ באופן חד משמעי, בלי תלות במצב התהליך. ב-POSIX הוא מתחיל ב-`/`, למשל `/home/shoval/data.csv`. ב-Windows הוא מתחיל באות כונן, למשל `C:\Users\shoval\data.csv`.

**Relative path, נתיב יחסי**: נתיב שאינו מתחיל בשורש, ולכן נפתר ביחס לתיקייה הנוכחית של התהליך. `data.csv`, `./data.csv` ו-`../shared/data.csv` הם כולם נתיבים יחסיים.

**Current working directory (cwd), תיקיית עבודה נוכחית**: תכונה של כל תהליך, לא של המשתמש ולא של הקובץ. כאשר תהליך מבקש מהקרנל לפתוח נתיב יחסי, הקרנל מצרף אותו ל-cwd של אותו תהליך. `pwd` בשורת הפקודה מדפיס אותה, `os.getcwd()` ב-Python מחזיר אותה, ו-`cd` משנה אותה עבור ה-shell בלבד.

**`.` ו-`..`**: `.` הוא רכיב שמצביע על התיקייה עצמה, ולכן `./data.csv` ו-`data.csv` שקולים. `..` מצביע על תיקיית ההורה. שניהם רכיבים אמיתיים שקיימים בכל תיקייה, לא סימנים שה-shell ממציא.

**`~`, tilde**: קיצור לתיקיית הבית של המשתמש. הרחבה שלו נעשית על ידי ה-shell לפני שהפקודה בכלל רצה. תוכנית שמקבלת את המחרוזת `~/data.csv` בתוך קובץ config לא תפתח כלום, כי אף אחד לא הרחיב אותה עבורה. ב-Python מרחיבים במפורש עם `os.path.expanduser`.

## דוגמה מחושבת

נניח את העץ הזה:

```
/home/shoval/
    project/
        main.py
        data/
            input.csv
    shared/
        input.csv
```

נריץ מתוך `project`:

```
cd /home/shoval/project
pwd
# /home/shoval/project

python -c "print(open('data/input.csv').readline())"
# נפתר ל-/home/shoval/project/data/input.csv

python -c "print(open('../shared/input.csv').readline())"
# נפתר ל-/home/shoval/shared/input.csv
```

עכשיו אותה פקודה בדיוק, מתיקייה אחרת:

```
cd /home/shoval
python -c "print(open('data/input.csv').readline())"
# FileNotFoundError: [Errno 2] No such file or directory: 'data/input.csv'
```

המחרוזת לא השתנתה. ה-cwd השתנה, ולכן היעד השתנה.

הפתרון המקובל הוא לחשב נתיב מוחלט מתוך מיקום הקובץ עצמו, לא מתוך ה-cwd:

```python
from pathlib import Path
HERE = Path(__file__).resolve().parent
data = HERE / "data" / "input.csv"
print(data)
# /home/shoval/project/data/input.csv
```

`__file__` הוא נתיב הקובץ שרץ, `resolve()` הופך אותו למוחלט ופותר symlinks, ו-`parent` מוריד את שם הקובץ. עכשיו ה-cwd של מי שהריץ את הסקריפט לא רלוונטי.

## המקרה שמפיל את האינטואיציה

**כלי אחד יכול לשכתב את הנתיב שלך לפני שהתוכנית רואה אותו.**

ברפוזיטורי הזה זה מתועד ב-`CLAUDE.md`: Git Bash על Windows מריץ תרגום נתיבים אוטומטי, מנגנון שנקרא **MSYS path conversion, המרת נתיבי MSYS**. כל ארגומנט שנראה כמו נתיב POSIX מוחלט, כלומר מתחיל ב-`/`, מומר לנתיב Windows לפני שהתוכנית מקבלת אותו. כאשר מעבירים למערכת בדיקות את הראוט `/`, כלומר עמוד הבית של האתר, Git Bash לא רואה ראוט. הוא רואה את השורש, ומעביר לתוכנית משהו בסגנון `C:/Program Files/Git/`.

הכשל שנוצר לא נראה כמו כשל נתיבים בכלל. הוא הופיע ככשל websocket, שלוש פעמים ברצף, כי ה-harness ניסה לנווט לכתובת חסרת משמעות. הנתיב היה נכון, הקוד היה נכון, והשכבה שביניהם החליפה את הערך.

זה המקרה הכללי שכדאי לזכור: נתיב עובר דרך shell, דרך container, דרך CI ודרך תרגום פלטפורמה, ולכל אחת מהשכבות האלה מותר לגעת בו. כשנתיב מתנהג בצורה בלתי אפשרית, הדפס אותו בדיוק כפי שהתוכנית קיבלה אותו לפני שאתה מחפש באג בלוגיקה.

## טעויות נפוצות

1. **הנחה ש-cwd הוא התיקייה שבה הקוד יושב**. הוא התיקייה שממנה הופעל התהליך. סקריפט שעובד כשמריצים אותו מתוך התיקייה שלו וקורס כשמריצים אותו מהשורש סובל מזה בדיוק. התיקון הוא `Path(__file__).resolve().parent`, לא `cd` נוסף לפני ההרצה.

2. **חיבור נתיבים בעזרת שרשור מחרוזות**. `base + "/" + name` מייצר `//` כפול כאשר `base` כבר מסתיים במפריד, ונשבר לגמרי כאשר `name` הוא מוחלט. `os.path.join` ו-`pathlib` מטפלים בשני המקרים; שים לב ש-`join` עם רכיב מוחלט זורק את כל מה שקדם לו, וזו התנהגות מכוונת ולא באג.

3. **הכנסת קלט משתמש לתוך נתיב בלי בדיקה**. `open(base + user_input)` עם קלט `../../etc/passwd` יוצא מהתיקייה המיועדת. זו חולשת **path traversal, מעבר נתיב**. הבדיקה הנכונה היא לפתור לנתיב מוחלט ואז לוודא שהוא נמצא מתחת לבסיס: `Path(base).resolve() in candidate.resolve().parents`.

4. **הסתמכות על `~` בתוך קובץ הגדרות**. ה-shell מרחיב tilde, אבל `json.load` לא. נתיב `~/data` בקובץ config יגיע לקוד כמחרוזת מילולית ויתפרש כשם תיקייה בשם `~`.

5. **התייחסות לאותיות רישיות כמשמעותיות בכל מקום**. מערכת הקבצים של Linux רגישה לרישיות ו-`Data.csv` שונה מ-`data.csv`. ברירת המחדל של Windows ו-macOS אינה רגישה. קוד שנכתב על מחשב נייד ונדחף ל-CI על Linux נכשל בדיוק כאן.

## מתי זה לא משנה

בסקריפט חד פעמי שרץ בתיקייה אחת ידועה, נתיב יחסי קצר קריא יותר מנתיב מוחלט ארוך, ואין סיבה לבנות `pathlib` סביבו. הסחר הוא בין קריאוּת לחוסן: נתיב יחסי קצר וקריא אבל תלוי במצב, נתיב מוחלט ארוך אבל חסין. ברגע שהקוד רץ גם ב-CI, גם בקונטיינר, או גם ממקום שאתה לא בוחר, החוסן מנצח. בראיונות backend ו-DevOps הנושא כמעט תמיד מגיע דרך path traversal, ולא דרך הגדרת נתיב מוחלט.
