# צינורות והפניה: תרגול

עכשיו תבנה שרשראות בעצמך, ותגלה שהחוליה שנראית הכי תמימה היא זו שמחזירה תשובה שגויה בשקט.

## מה תדע בסוף

לבנות שרשרת בת שלוש עד ארבע חוליות שמפיקה תשובה מלוג אמיתי, לדעת מתי חוליה מיותרת, ולזהות את הצירוף שמחזיר מספר שנראה סביר ואינו נכון.

## האינטואיציה

חזרה לשתי המכונות המוברגות זו לזו מהיחידה הקודמת. עכשיו אתה מוסיף מכונה שלישית ורביעית לטור.

הדבר החדש שמתגלה רק כשהטור מתארך: כל מכונה בטור רואה **רק את מה שהמכונה שלפניה הוציאה**, ולא את המקור. אם מכונה שלישית מצפה שהחומר יגיע ממוין, והמכונה שלפניה לא מיינה, היא לא תתלונן. היא תעבוד יפה ותוציא תוצאה שגויה. אין בטור שום מנגנון שאומר "קיבלתי קלט שלא במבנה שציפיתי לו".

זה ההבדל בין שרשרת שנופלת לשרשרת ששקרה לך.

## ההגדרות המדויקות

**`grep`**: מסננת שורות לפי תבנית. `grep -c` סופרת התאמות בעצמה, בלי חוליה נוספת.

**`sort`**: ממיינת שורות. היא חייבת לקרוא את **כל** הקלט לפני שהיא מוציאה שורה אחת, ולכן היא נקודת עצירה בטור: כל מה שאחריה מחכה לה.

**`uniq`**: מכווצת שורות זהות **סמוכות בלבד**. היא לא מחפשת כפילויות בכל הקובץ. `uniq -c` מוסיפה מונה. זו הסיבה ש-`uniq` כמעט תמיד באה אחרי `sort`.

**`wc -l`**: סופרת שורות.

**`cut -d" " -f2-`**: חותכת שדות מכל שורה לפי מפריד.

**`tee file`**: כותבת את מה שעובר דרכה גם לקובץ וגם הלאה בטור. היא החוליה היחידה כאן שמאפשרת להסתכל באמצע שרשרת בלי לשבור אותה.

## דוגמה מחושבת

הקובץ `log.txt`:

```
ERROR disk full
INFO ok
ERROR timeout
WARN slow
ERROR timeout
```

**דירוג השגיאות הנפוצות:**

```
grep ERROR log.txt | sort | uniq -c | sort -rn
```

```
      2 ERROR timeout
      1 ERROR disk full
```

ארבע חוליות: סנן, מיין כדי שהכפילויות ייפגשו, כווץ עם מונה, מיין שוב לפי המונה בסדר יורד. `-rn` הוא `-r` הפוך ו-`-n` מספרי, כי בלי `-n` המיון היה לקסיקוגרפי ו-10 היה מופיע לפני 9.

**חוליה מיותרת:**

```
grep -c ERROR log.txt
grep ERROR log.txt | wc -l
```

```
3
3
```

שתיהן נכונות. הראשונה עושה זאת בתהליך אחד.

**להסתכל באמצע בלי לשבור:**

```
grep ERROR log.txt | tee found.txt | wc -l
```

```
3
```

המסך קיבל את הספירה, ו-`found.txt` שמר את שלוש השורות עצמן. כשמנסים לאתר איפה בטור הנתונים התקלקלו, `tee` היא הכלי, לא הוצאת החוליות אחת אחת.

## המקרה שמפיל את האינטואיציה

`uniq` בלי `sort` לפניה. הקלט הוא שלוש שורות: `a`, `b`, `a`.

```
uniq -c u.txt
```

```
      1 a
      1 b
      1 a
```

```
sort u.txt | uniq -c
```

```
      2 a
      1 b
```

בלי המיון, שתי ה-`a` לא היו סמוכות, ולכן `uniq` לא ראתה אותן ככפילות. היא לא נכשלה ולא הזהירה. היא החזירה שלוש שורות שנראות כמו תשובה לגיטימית, וקוד היציאה היה 0.

זה הדפוס שצריך להיחרט: **חוליה בטור לא מאמתת את מבנה הקלט שלה**. כשתשובה נראית סבירה ובכל זאת מרגישה נמוכה, בדוק אם חוליה כלשהי הניחה סדר שלא סיפקת לה.

## טעויות נפוצות

1. **"`uniq` מסירה כפילויות מהקובץ"**. רק כפילויות סמוכות. בלי `sort` לפניה היא מחזירה תשובה שגויה בשקט, כמו למעלה.

2. **"`sort -n` ו-`sort` דומים"**. `sort` ברירת מחדל ממיינת כטקסט, ולכן `10` בא לפני `9`. בכל מיון של מונים צריך `-n`.

3. **"אם הוספתי חוליה והתוצאה השתנתה, החוליה החדשה שגויה"**. לא בהכרח. לפעמים היא חשפה שהתוצאה הקודמת הייתה שגויה מלכתחילה. הוספת `sort` לפני `uniq` היא בדיוק המקרה הזה.

4. **"`cat file | grep x` ו-`grep x file` שקולים"**. התוצאה זהה, אבל הראשון מפעיל תהליך מיותר. חשוב מזה: `grep` על קובץ יודעת את שם הקובץ ויכולה להדפיס אותו, ובקלט מהצינור אין לה שם.

5. **"אפשר לנפות שרשרת ארוכה על ידי הסתכלות בפלט הסופי"**. הפלט הסופי הוא בדיוק מה שלא מספר לך איפה זה נשבר. חתוך את הטור, או השתמש ב-`tee` באמצע.

## מתי זה לא משנה

על קובץ בן חמש שורות שאתה קורא בעיניים, אף אחת מהמלכודות האלה לא תעלה לך כלום. הן מתחילות לעלות כשהקלט גדול מכדי לבדוק ידנית, וזה בדיוק המצב שבו התוצאה השגויה נראית סבירה ואין לך איך לדעת.

בשלב מסוים שרשרת של שש חוליות נעשית פחות קריאה מסקריפט Python בן עשר שורות שעושה את אותו דבר עם שמות משתנים. שרשרת היא כלי לתשובה מהירה, לא ארכיטקטורה.
