# זרמי קלט ופלט וקודי יציאה: תרגול

ידעת שיש שלושה חריצים. עכשיו תריץ חמש פקודות ותנבא, לפני כל אחת, לאן בדיוק ילך כל בית.

## מה תדע בסוף

לכתוב הפניה שמפרידה פלט רגיל משגיאות בפקודה אחת, לדעת למה סדר ההפניות משנה, ולהשתמש בקוד היציאה כדי להחליט מה קורה אחר כך.

## האינטואיציה

חזרה למכונת העותקים מהיחידה הקודמת: חריץ כניסה, מגש פלט, מגש שגיאות. עכשיו אתה לא רק יודע שהם קיימים, אתה מזיז את הצינורות שמחוברים אליהם.

הנקודה היחידה שמפילה אנשים כאן: כשאתה מחבר צינור, אתה מעתיק **לאן שהצינור השני מצביע ברגע הזה**. אתה לא נותן לו שם ואתה לא יוצר קישור חי. אם אחר כך תזיז את הצינור הראשון, השני יישאר במקום שאליו הצבעת קודם. כל טעות ההפניה הנפוצה ביותר היא בדיוק זה.

## ההגדרות המדויקות

**Redirection, הפניה**: שינוי היעד של ערוץ לפני שהתוכנית מתחילה לרוץ. ה-shell מבצע אותו, לא התוכנית.

- `> file` מפנה את stdout (מתאר 1) לקובץ, ודורס אותו.
- `>> file` מוסיף לסוף הקובץ במקום לדרוס.
- `2> file` מפנה את stderr (מתאר 2).
- `2>&1` מפנה את stderr לאן ש-stdout מצביע **באותו רגע**. ה-`&` אומר "המתאר מספר 1", לא "קובץ בשם 1".
- `&> file` קיצור של bash לשניהם יחד, ומחסן מבעיית הסדר.

**Null device, התקן האפס**: `/dev/null` הוא קובץ מיוחד שבולע כל מה שנכתב אליו. `> /dev/null` פירושו "אני לא רוצה את הפלט הזה", לא "אל תדפיס".

**Short-circuit, קיצור מסלול**: `a && b` מריץ את `b` רק אם `a` החזירה 0. `a || b` מריץ את `b` רק אם `a` החזירה משהו שאינו 0. שניהם קוראים את קוד היציאה, לא את הפלט.

## דוגמה מחושבת

הרץ כל אחת מהן ובדוק שהפלט אצלך זהה.

**תרגיל 1: פקודה אחת, שני זרמים, שני קבצים.**

```
ls /tmp /nosuchdir > out.txt 2> err.txt
echo "exit: $?"
```

```
exit: 2
```

`out.txt` מכיל את תוכן `/tmp`, ו-`err.txt` מכיל שורה אחת:

```
ls: cannot access '/nosuchdir': No such file or directory
```

שים לב שהפקודה גם הצליחה חלקית וגם נכשלה. `ls` הדפיסה את מה שיכלה ל-stdout, את מה שלא ל-stderr, והחזירה 2. זרם אחד לא מבטל את השני.

**תרגיל 2: stderr עוקף צינור.**

```
ls /nosuchdir | wc -l
```

```
ls: cannot access '/nosuchdir': No such file or directory
0
```

הודעת השגיאה הופיעה על המסך למרות ה-pipe, ו-`wc` ספרה 0 שורות. `|` מחבר רק את stdout. זו הסיבה ששרשרת עיבוד יכולה להיראות "ריקה" בזמן שהשגיאה צועקת מולך.

**תרגיל 3: קוד היציאה מחליט.**

```
ls /tmp > /dev/null 2>&1 && echo "ok branch" || echo "fail branch"
ls /nosuchdir > /dev/null 2>&1 && echo "ok branch" || echo "fail branch"
```

```
ok branch
fail branch
```

הפלט של שתי הפקודות נבלע. מה שנשאר להחליט לפיו הוא רק המספר שהן החזירו.

## המקרה שמפיל את האינטואיציה

שתי השורות הבאות נראות כמו אותה שורה בסדר אחר. הן לא עושות אותו דבר.

```
ls /nosuchdir > a.txt 2>&1
```

המסך שקט. `a.txt` מכיל את הודעת השגיאה.

```
ls /nosuchdir 2>&1 > b.txt
```

השגיאה מודפסת על המסך. `b.txt` ריק לגמרי.

הסיבה היא ההגדרה למעלה. בשורה הראשונה `>` הזיז את stdout לקובץ, ורק אחר כך `2>&1` העתיק את היעד הנוכחי של stdout, שהוא כבר הקובץ. בשורה השנייה `2>&1` רץ ראשון והעתיק את היעד של stdout באותו רגע, שהוא עדיין המסך; אחר כך `>` הזיז את stdout לקובץ, ו-stderr נשאר מחובר למסך.

ההפניה מעתיקה יעד, לא שם. תקרא את השורה משמאל לימין כמו שה-shell קורא אותה, ולא תטעה בזה שוב.

## טעויות נפוצות

1. **"`2>&1` שולח שגיאות ל-stdout"**. לא. הוא שולח אותן לאן ש-stdout מצביע כרגע. אם stdout לא הופנה, זה המסך; אם הופנה קודם, זה הקובץ. ההבדל הוא כל התרגיל הזה.

2. **"`> /dev/null` מכבה את השגיאות"**. הוא מכבה רק את stdout. שגיאות ימשיכו להגיע למסך עד ש-`2>` או `2>&1` יטפל בהן.

3. **"אם ה-pipeline החזיר שורות ריקות, הפקודה הראשונה נכשלה בשקט"**. היא כנראה צעקה, אבל ל-stderr, ש-`|` לא מעביר. בדוק את קוד היציאה, או הוסף `2>&1` לפני ה-pipe אם אתה באמת רוצה את השגיאות בשרשרת.

4. **"`>` ו-`>>` דומים מספיק"**. `>` דורס את הקובץ ברגע שה-shell פותח אותו, עוד לפני שהפקודה רצה. `cmd > same.txt` שקורא מ-`same.txt` ימחק אותו לפני הקריאה.

## מתי זה לא משנה

בפקודה בודדת שאתה מריץ ידנית ומסתכל על המסך, אין הבדל מעשי: הכל מגיע לאותו חלון. ההפרדה מתחילה לעלות כסף ברגע שמשהו אוטומטי קורא את הפלט: סקריפט, שלב ב-CI, או pipeline. שם ערבוב של שגיאה לתוך הנתונים הוא באג שקט, ולכן `2>&1` במקום הלא נכון הוא תקלה שמתגלה שבוע אחרי.

בראיון, השאלה על סדר ההפניות בודקת אם אתה יודע שה-shell מבצע אותן לפי סדר משמאל לימין לפני הרצת התוכנית, ולא אם שיננת טבלה.
