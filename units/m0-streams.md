# זרמי קלט ופלט וקודי יציאה

כל תוכנית שהרצת פתחה שלושה ערוצים שלא ביקשת. ברגע שתדע את שמותיהם, תוכל לחבר תוכניות אחת לשנייה ולדעת מה קרה כשהן נסגרות.

## מה תדע בסוף

להגיד מה הם stdin, stdout ו-stderr, לכוון כל אחד מהם בנפרד, ולקרוא קוד יציאה ולהסיק ממנו אם פקודה הצליחה.

## האינטואיציה

תחשוב על מכונת עותקים. יש לה חריץ לכניסת דף, מגש ליציאת עותק, ומגש נפרד לשגיאות. הכל מוכן לפני שאתה מכניס דף.

כל תוכנית קיבלה שלושה חריצים כאלה ברגע שהיא נפתחה. ה-shell חיבר אותם לטרמינל שלך כברירת מחדל. פקודות כמו `|` ו-`>` רק מחברות מחדש, הן לא יוצרות חריצים חדשים.

## ההגדרות המדויקות

**stdin, כניסה תקנית**: ערוץ הקלט של התוכנית. מספרו 0. ברירת מחדל: המקלדת.

**stdout, יציאה תקנית**: ערוץ הפלט הרגיל. מספרו 1. ברירת מחדל: החלון.

**stderr, יציאה שגויה**: ערוץ נפרד לשגיאות ואזהרות. מספרו 2. ברירת מחדל: אותו חלון. ה-shell לא מחבר אותו ל-stdout אוטומטית, אבל שניהם מגיעים למסך.

המספרים 0, 1, 2 הם **file descriptors, מתארי קבצים**: מספרים שלמים שמזהים ערוצים פתוחים. מערכת ההפעלה מנהלת כל ערוץ כקובץ פנימי.

**Exit code, קוד יציאה**: מספר שלם שתוכנית מחזירה כשהיא נסגרת. 0 פירושו הצלחה. כל מספר אחר מסמן כישלון. ה-shell שומר את הקוד האחרון במשתנה `$?`.

## דוגמה מחושבת

```
ls /tmp > out.txt 2> err.txt
echo "exit code: $?"
```

`>` כיוון את stdout לקובץ `out.txt`. `2>` כיוון את stderr לקובץ `err.txt`. קוד היציאה הוא 0 כי הפקודה הצליחה.

עכשיו עם נתיב שלא קיים:

```
ls /nosuchdir > out.txt 2> err.txt
echo "exit code: $?"
cat out.txt
cat err.txt
```

`out.txt` ריק, כי `ls` לא הדפיסה כלום ל-stdout. `err.txt` מכיל את הודעת השגיאה, כי `ls` שלחה אותה ל-stderr. קוד היציאה הוא 2 (ב-bash, "No such file or directory").

## המקרה שמפיל את האינטואיציה

`curl` שולח את progress-bar ל-stderr ואת הנתונים ל-stdout:

```
curl https://example.com > body.txt
```

המסך מציג שורת progress, אבל `body.txt` מכיל רק את ה-HTML. אם מעבירים את הפלט ל-pipeline מבלי לדעת זאת, שורת ה-progress נכנסת לפלט ומזהמת את הנתונים.

הפתרון: `curl -s https://example.com > body.txt` מדכא את stderr של curl.

## טעויות נפוצות

1. **"כל מה שמודפס הוא stdout"**. לא. stderr מגיע גם הוא למסך כברירת מחדל, ולכן לא ניתן להבחין ביניהם בעין בלי לכוון כל אחד בנפרד.

2. **"קוד יציאה 0 פירושו שגיאה"**. ההפך. 0 הוא הצלחה. הבלבול בא מ-C, שבה null (0) מסמן שגיאה בהקשרים אחרים. בקוד יציאה, 0 תמיד הצלחה.

3. **"אם לא הודפס כלום, הפקודה הצליחה"**. כלים רבים מצליחים בשקט. הסימן האמין הוא קוד היציאה, לא הפלט.

4. **"סדר ה-redirections לא משנה"**. `cmd > file 2>&1` שם גם stdout וגם stderr ב-file. `cmd 2>&1 > file` שם רק stdout ב-file, כי `2>&1` מחבר stderr לאן שstdout היה באותו רגע, ובאותו רגע הוא עדיין המסך.

## מתי זה לא משנה

כשמריצים פקודה בודדת ובודקים רק אם הצליחה, אפשר להתעלם מ-stderr ולסמוך על קוד היציאה בלבד: `if ! command; then echo "failed"; fi`. ב-IDE מודרני שגיאות build מוצגות בממשק ולא דרך stderr ישיר. הידע הזה קריטי בסקריפטים וב-CI.

## חיבור

stdin, stdout, stderr הם מה שמאפשר pipes: הפקודה הבאה בשרשרת קוראת את stdout של הקודמת בתור stdin שלה. בלי ההפרדה הזו שרשרת כמו `cat log.txt | grep ERROR | wc -l` לא הייתה אפשרית. היחידה הבאה, `m0-pipes`, בונה על הידע הזה ישירות.
