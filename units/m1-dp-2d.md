# תכנון דינמי דו-ממדי
כשהתשובה לשאלה "כמה דרכים יש?" תלויה גם בשורה וגם בעמודה שבה עומדים, טבלה קטנה ממולאת שורה-שורה פותרת את הכל.

## מה תדע בסוף
תדע לגדיר State דו-ממדי, לכתוב Recurrence ולממש Bottom-Up DP בטבלה; תוכל לפתור Unique Paths, Longest Common Subsequence ו-Edit Distance; תדע לקבוע את גודל הטבלה, את Base Cases ואת סדר מילוי הנכון.

## האינטואיציה

דמיין לוח ריק בגודל 3 על 3. רובוט עומד בפינה השמאלית העליונה (0,0) ורוצה להגיע לפינה הימנית התחתונה (2,2). הוא יכול לצעוד רק ימינה או מטה. כמה נתיבים שונים יש לו?

כל תא שואל: "כמה נתיבים מגיעים אליי?" הנתיבים שמגיעים ל-(i,j) הם הנתיבים שהגיעו ל-(i-1,j) (מעל) פלוס אלו שהגיעו ל-(i,j-1) (משמאל). הלוח ממלא את עצמו בסדר שורות, כל תא מסתכל על שני שכניו שכבר מולאו.

זה **2D Dynamic Programming, תכנון דינמי דו-ממדי**: פתרון בעיה על-ידי מילוי טבלה דו-ממדית שכל **State, מצב** שבה תלוי רק במצבים שכבר מחושבים.

## הפורמליזם

### שלושת הרכיבים

**State**: הגדרה של מה שכל תא בטבלה מאחסן. בדוגמה: `dp[i][j]` = מספר הנתיבים מ-(0,0) עד (i,j).

**Transition (מעבר)**: הנוסחה שמחשבת `dp[i][j]` מתאים שכבר מולאו.
\[
dp[i][j] = dp[i-1][j] + dp[i][j-1]
\]

**Base Cases**: תאים שהנוסחה אינה חלה עליהם. כאן: כל שורה 0 ועמודה 0 שווים 1, כי יש בדיוק נתיב אחד לכל תא בהם (כולה ימינה, או כולה מטה).

### Unique Paths

```python
def unique_paths(m: int, n: int) -> int:
    dp = [[1] * n for _ in range(m)]   # base: שורה 0 ועמודה 0
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i-1][j] + dp[i][j-1]
    return dp[m-1][n-1]
```

מורכזות: זמן \(O(m \cdot n)\), זיכרון \(O(m \cdot n)\). ניתן לצמצם ל-\(O(n)\) בזיכרון על-ידי שמירת שורה אחת בלבד.

### Longest Common Subsequence

נתונות שתי מחרוזות `s1`, `s2`. **Subsequence, תת-סדרה** של מחרוזת היא בחירת תווים לפי הסדר המקורי (לא בהכרח רצופים). ה-**LCS, תת-סדרה משותפת ארוכה ביותר** מחפשת את ה-Subsequence הארוכה ביותר שמשותפת לשתיהן.

**State**: `dp[i][j]` = אורך ה-LCS של `s1[:i]` ו-`s2[:j]`.

**Transition**:
\[
dp[i][j] = \begin{cases} dp[i-1][j-1] + 1 & \text{אם } s1[i-1] = s2[j-1] \\ \max(dp[i-1][j],\ dp[i][j-1]) & \text{אחרת} \end{cases}
\]

```python
def lcs(s1: str, s2: str) -> int:
    m, n = len(s1), len(s2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]   # (m+1)x(n+1) עם שורת-0 ועמודת-0
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

### Edit Distance

**State**: `dp[i][j]` = מספר הפעולות המינימלי (insert, delete, replace) להמרת `s1[:i]` ל-`s2[:j]`.

**Transition**:
\[
dp[i][j] = \begin{cases} dp[i-1][j-1] & \text{אם } s1[i-1] = s2[j-1] \\ 1 + \min(dp[i-1][j],\ dp[i][j-1],\ dp[i-1][j-1]) & \text{אחרת} \end{cases}
\]

**Base**: `dp[i][0] = i` (מחיקת i תווים), `dp[0][j] = j` (הוספת j תווים).

## דוגמה מחושבת

Unique Paths עם `m=3, n=3`:

| | j=0 | j=1 | j=2 |
|---|---|---|---|
| i=0 | 1 | 1 | 1 |
| i=1 | 1 | 2 | 3 |
| i=2 | 1 | 3 | 6 |

`dp[1][1] = dp[0][1] + dp[1][0] = 1 + 1 = 2`  
`dp[1][2] = dp[0][2] + dp[1][1] = 1 + 2 = 3`  
`dp[2][1] = dp[1][1] + dp[2][0] = 2 + 1 = 3`  
`dp[2][2] = dp[1][2] + dp[2][1] = 3 + 3 = 6`

תשובה: 6 נתיבים. ניתן לאמת: \(\binom{4}{2} = 6\) (בחר 2 צעדים ימינה מתוך 4 כולל).

LCS של "ABCDE" ו-"ACE":

| | "" | A | C | E |
|---|---|---|---|---|
| "" | 0 | 0 | 0 | 0 |
| A | 0 | 1 | 1 | 1 |
| B | 0 | 1 | 1 | 1 |
| C | 0 | 1 | 2 | 2 |
| D | 0 | 1 | 2 | 2 |
| E | 0 | 1 | 2 | 3 |

LCS = 3, הסדרה "ACE".

## המקרה שמפיל את האינטואיציה

### סדר המילוי קובע הכל

ב-LCS, `dp[i][j]` תלוי ב-`dp[i-1][j-1]`, `dp[i-1][j]` ו-`dp[i][j-1]`. סדר הלולאות חייב להיות: i חיצוני, j פנימי, ובתוך כל שורה - j גדל. ניסיון למלא j לפני i גורם ל-`dp[i-1][j-1]` להיות עדיין 0 (ערך אינציאליזציה) במקום הערך הנכון. הבאג שקט: לא תהיה שגיאה, רק תשובה לא נכונה.

לפני שכותבים לולאות, שרטט חץ מ-`dp[i][j]` לכל תא שהוא תלוי בו. הלולאות חייבות למלא תאים לפי כיוון החצים.

## טעויות נפוצות

**1. גודל טבלה שגוי**

ב-LCS ו-Edit Distance הטבלה היא `(m+1) x (n+1)` כדי לאחסן Base Case של מחרוזת ריקה. גודל `m x n` גורם ל-IndexError כש-i=0 ומנסים לגשת ל-`dp[i-1][j-1]`.

**2. `dp = [[0]*n]*m` במקום `[[0]*n for _ in range(m)]`**

הכפל יוצר m הפניות לאותה רשימה: שינוי `dp[0][1]` ישנה `dp[1][1]` וכל שאר השורות. Python אינו מעתיק את הרשימה הפנימית, רק מרבה הפניות אליה.

**3. Base Cases חלקיים עם מכשולים**

ב-Unique Paths עם מכשולים (obstacle grid), תא מכשול שווה 0. אבל Base Case חייב להתחשב במכשולים: מכשול בשורה 0 הופך את כל התאים ממנו ימינה ל-0 גם הם. אם ממלאים את כל שורה 0 כ-1, מקבלים תוצאה שגויה.

**4. בלבול בין Subsequence ל-Substring**

LCS מחפש Subsequence (תווים לא-רצופים בסדר). **Longest Common Substring, תת-מחרוזת משותפת ארוכה ביותר** מחייב רציפות: המעבר שונה לגמרי (`dp[i][j] = dp[i-1][j-1] + 1` רק בהתאמה, אחרת `dp[i][j] = 0`). השניים חולקים שם דומה אבל לא פתרון.

## מתי זה לא משנה

**כשהבעיה חד-ממדית**: Fibonacci, Climbing Stairs, House Robber - כולם 1D DP, אין צורך בטבלה שלמה.

**כשמרחב ה-State גדול מדי**: `m x n` יכול להיות 10^6 בכל ציר. ב-Edit Distance עם מחרוזות ענקיות משתמשים ב-Space Optimization (שמירת שורה אחת) או בגישות אחרות לגמרי.

**בראיון**: שני מחרוזות + "longest/minimum" = LCS או Edit Distance. "כמה דרכים בגריד" = Unique Paths. מחיר: \(O(m \cdot n)\) זמן וזיכרון. אם מבקשים טוב יותר - שאלה מוצדקת לשאול את המראיין.

## חיבור

יחידה זו שייכת ל-M1 (DS&A, node `dsa`, tree `systems`). 2D DP מרחיב 1D DP (m1-dp-1d): ה-State גדל מסקלר לזוג. Edit Distance נמצא כמעט בכל spell-checker, git diff וכלי Alignment בביואינפורמטיקה.

**מה זה מאפשר**:
- **m1-dp-2d-drill**: תרגול על Unique Paths עם מכשולים, LCS ו-Edit Distance
- **m1-graph-traversal**: BFS על גריד הוא מעבר דו-ממדי, רעיון קרוב
- **m1-intervals**: גישת DP על קטעים משתמשת לעתים ב-2D
