# חמדני (Greedy)
בכל צומת בחר את האפשרות שנראית הכי טובה עכשיו; כשזה עובד, מגיעים לאופטימום גלובלי במחיר של מעבר יחיד.

## מה תדע בסוף
תדע לזהות את הסימנים שמצביעים על פתרון חמדני, תממש תחרות פעילויות ב-Python, ותסביר למה בחירה לפי זמן סיום מניבה מקסימום פעילויות.

## האינטואיציה

דמיין שיש לך יום עם פגישות שחופפות אחת לשנייה ואתה רוצה להיפגש עם כמה שיותר אנשים. הדרך: תמיד קבל את הפגישה שנגמרת **הכי מוקדם**. ברגע שהיא נגמרת, שוב בחר את הבאה שנגמרת הכי מוקדם ועדיין פנויה.

זו הגישה החמדנית: **בכל שלב קבל את ההחלטה שנראית הכי טובה באותו רגע**, בלי לחזור אחורה. לא תמיד זה עובד, אבל כשעובד הוא פשוט ומהיר.

**Greedy Algorithm, אלגוריתם חמדני**: גישה שבונה פתרון צעד-צעד, בכל שלב בוחרת את ה**Locally Optimal Choice, הבחירה המקומית האופטימלית**, בתקווה שהצטברות הבחירות הללו תייצר **Globally Optimal Solution, פתרון גלובלי אופטימלי**.

**Greedy Choice Property, תכונת הבחירה החמדנית**: קיים פתרון אופטימלי שמכיל את הבחירה החמדנית. זו התכונה שמבדילה בעיות שחמדני עובד בהן מאלה שלא.

**Exchange Argument, ארגומנט ההחלפה**: הדרך להשתכנע שחמדני עובד: אם לפתרון אחר יש בחירה שונה מהחמדנית, ניתן "להחליף" אותה בבחירה החמדנית מבלי לפגוע בתוצאה. אם ההחלפה אף פעם לא מרעה, החמדני אופטימלי.

## ההגדרות המדויקות

### תחרות פעילויות (Activity Selection)

קלט: n פעילויות, לכל פעילות i יש זמן התחלה \(s_i\) וזמן סיום \(f_i\) כאשר \(s_i < f_i\).

שתי פעילויות **תואמות** (Compatible) אם הן לא חופפות: \(f_i \le s_j\) או \(f_j \le s_i\).

המטרה: מצא תת-קבוצה מקסימלית של פעילויות שכולן תואמות אחת לשנייה.

**האלגוריתם החמדני**:
1. מיין לפי זמן סיום בסדר עולה.
2. קח תמיד את הפעילות שנגמרת הכי מוקדם ותואמת לאחרון שנבחר.

**מורכבות**: \(O(n \log n)\) למיון, \(O(n)\) לסריקה, סה"כ \(O(n \log n)\). זיכרון \(O(n)\) לרשימת הנבחרות.

### מטבעות (Coin Change - מערכות קנוניות בלבד)

קלט: מערך ערכי מטבעות ויעד amount.

הגישה החמדנית: תמיד קח את המטבע הכי גדול שלא עולה על הסכום הנותר.

**חשוב**: זה עובד רק עבור **Canonical Coin Systems, מערכות מטבעות קנוניות** כמו \(\{1, 5, 10, 25\}\). למערכות שרירותיות נדרש Dynamic Programming.

### Interval Scheduling Maximization - ניסוח כללי

\[
\text{maximize } |S| \text{ subject to: } \forall i,j \in S,\; f_i \le s_j \text{ or } f_j \le s_i
\]

## דוגמה מחושבת

### תחרות פעילויות

פעילויות: `[(1,4),(3,5),(0,6),(5,7),(3,8),(8,11),(8,12),(12,14)]`

מיון לפי זמן סיום:
`[(1,4),(3,5),(0,6),(5,7),(3,8),(8,11),(8,12),(12,14)]`

| צעד | פעילות | last_end לפני | start >= last_end? | פעולה | last_end אחרי |
|-----|--------|--------------|-------------------|-------|--------------|
| 1 | (1,4) | 0 | 1 >= 0: כן | קח | 4 |
| 2 | (3,5) | 4 | 3 >= 4: לא | דלג | 4 |
| 3 | (0,6) | 4 | 0 >= 4: לא | דלג | 4 |
| 4 | (5,7) | 4 | 5 >= 4: כן | קח | 7 |
| 5 | (3,8) | 7 | 3 >= 7: לא | דלג | 7 |
| 6 | (8,11) | 7 | 8 >= 7: כן | קח | 11 |
| 7 | (8,12) | 11 | 8 >= 11: לא | דלג | 11 |
| 8 | (12,14) | 11 | 12 >= 11: כן | קח | 14 |

תוצאה: `[(1,4),(5,7),(8,11),(12,14)]` - 4 פעילויות, המקסימום האפשרי.

```python
def activity_selection(activities: list[tuple[int, int]]) -> list[tuple[int, int]]:
    sorted_acts = sorted(activities, key=lambda x: x[1])
    selected = [sorted_acts[0]]
    last_end = sorted_acts[0][1]

    for start, end in sorted_acts[1:]:
        if start >= last_end:
            selected.append((start, end))
            last_end = end

    return selected

acts = [(1,4),(3,5),(0,6),(5,7),(3,8),(8,11),(8,12),(12,14)]
print(activity_selection(acts))
# [(1, 4), (5, 7), (8, 11), (12, 14)]
```

### מטבעות קנוניות: יעד 41 סנט

מטבעות: `[1, 5, 10, 25]` (מגדול לקטן: 25, 10, 5, 1)

| שלב | נותר | מטבע | הסבר |
|-----|------|------|------|
| 1 | 41 | 25 | הכי גדול <= 41 |
| 2 | 16 | 10 | הכי גדול <= 16 |
| 3 | 6 | 5 | הכי גדול <= 6 |
| 4 | 1 | 1 | הכי גדול <= 1 |

4 מטבעות. זהו המינימום עבור מערכת קנונית.

```python
def greedy_coins(coins: list[int], amount: int) -> list[int]:
    coins = sorted(coins, reverse=True)
    result = []
    for coin in coins:
        while amount >= coin:
            result.append(coin)
            amount -= coin
    return result

print(greedy_coins([1, 5, 10, 25], 41))
# [25, 10, 5, 1]
```

## המקרה שמפיל את האינטואיציה

### מטבעות לא קנוניות

מטבעות: `[1, 3, 4]`, יעד: 6.

חמדני: 4 + 1 + 1 = **3 מטבעות**.

האופטימום: 3 + 3 = **2 מטבעות**.

החמדני נכשל. בחירת 4 נראית הגיונית (הכי גדולה שמאפשרת המשך), אבל היא משאירה שארית שלא ניתן לכסות ביעילות.

```python
# הפתרון הנכון לבעיה הכללית: Dynamic Programming
def dp_coins(coins: list[int], amount: int) -> int:
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

print(dp_coins([1, 3, 4], 6))   # 2
print(dp_coins([1, 5, 10, 25], 41))  # 4
```

### 0/1 Knapsack

נתונים פריטים עם ערך ומשקל, קיבולת שק. מטרה: מקסם ערך.

חמדני לפי יחס `value/weight` נכשל לרוב. דוגמה:
- פריט A: ערך 10, משקל 5 (יחס 2.0)
- פריט B: ערך 6, משקל 4 (יחס 1.5)
- פריט C: ערך 6, משקל 4 (יחס 1.5)
- קיבולת: 8

חמדני: A (משקל 5), B לא נכנס (משקל 9 > 8) - סה"כ ערך 10.
אופטימום: B + C (משקל 8) - סה"כ ערך 12.

**כלל**: כשניתן לחלק פריטים (Fractional Knapsack), חמדני עובד. כש"הכל או כלום" (0/1 Knapsack), נדרש DP.

## טעויות נפוצות

**1. להניח שחמדני תמיד עובד**

רק כשיש Greedy Choice Property. לפני ישום, שאל: "האם בחירה מקומית טובה מובילה לאופטימום גלובלי?" אם אין הוכחה פשוטה - חשוב על DP.

**2. לשכוח למיין לפי הקריטריון הנכון**

תחרות פעילויות: מיין לפי **זמן סיום**, לא זמן התחלה ולא משך. מיון לפי זמן התחלה נותן תוצאה שגויה.

**3. `>` במקום `>=` בבדיקת תאימות**

`start >= last_end` נכון: פגישה שמתחילה בדיוק כשהקודמת נגמרת היא תואמת. `start > last_end` דולג על מקרה גבול חוקי.

**4. להחיל חמדני מטבעות על מערכת לא קנונית**

תמיד שאל בראיון: "האם המטבעות קנוניות?" לפני שמממשים חמדני. בלי אישור, בצע DP.

**5. לא לטפל ברשימה ריקה**

`sorted_acts[0]` קורס על רשימה ריקה. בראיון: בדוק `if not activities: return []` בתחילת הפונקציה.

## מתי זה לא משנה

**כשיש שתי constraints בו-זמנית**: בעיות עם תלות בין פריטים (0/1 Knapsack, String Edit Distance) שוברות את Greedy Choice Property. נדרש DP.

**כשn קטן (n < 15)**: Backtracking ממצה עובד ב-\(O(2^n)\) ומבטיח אופטימום גלובלי בלי לדאוג לתכונת הבחירה.

**בראיון**: הדגלים לחמדני הם "maximize number of" עם constraint יחיד, או "minimum cost to cover". שני constraints מצביעים לרוב על DP. TP טיפוסיים: Interval Scheduling, Jump Game, Gas Station, Task Scheduler.

**חמדני לעומת DP**:
- DP סורק **את כל** האפשרויות - נכון תמיד, \(O(n^2)\) ויותר.
- חמדני קובע בחירה אחת ועובר הלאה - נכון רק עם Greedy Choice Property, \(O(n \log n)\).
