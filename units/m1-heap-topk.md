# ערימה ו-top-k
כשצריך את 10 התוצאות הרלוונטיות ביותר מתוך מיליון רשומות, heap מביא אותך מ-\(O(n \log n)\) ל-\(O(n \log k)\) בלי למיין כלום.

## מה תדע בסוף
תדע מה זה min-heap ואיך הוא מיוצג כמערך, תדע להשתמש ב-heapq של פייתון לפתרון בעיות top-k, ותדע להחליט מתי heap עדיף על מיון.

## האינטואיציה
דמיין מיון עדיפות בחדר מיון של בית חולים. אתה לא צריך שכולם יסודרו לפי חומרת מצבם; אתה רק צריך שתמיד ידעת מיד מי הדחוף ביותר עכשיו. ה-heap עושה בדיוק זאת: הוא שומר רק ערבות אחת קטנה, שהמינימום (או המקסימום) תמיד בשורש, בלי למיין את כל שאר האלמנטים.

האינטואיציה הזאת עומדת לנו גם ב-top-k: אם מחפשים את k הגדולים מתוך n מספרים, לא צריך למיין את כולם. מספיק לשמור min-heap בגודל k. בכל פעם שמספר חדש גדול מהשורש, מכניסים אותו ומוציאים את הקטן. בסוף heap מכיל בדיוק את k הגדולים.

## ההגדרות המדויקות

**Min-heap, ערימת מינימום**: עץ בינארי שלם (complete binary tree, כלומר כל הרמות מלאות חוץ מהאחרונה שממולאת משמאל) שבו כל צומת קטן מצאאיו או שווה להם. תכונה זו נקראת **heap invariant, מאפיין הערימה**.

**Max-heap, ערימת מקסימום**: אותו מבנה, אבל כל צומת גדול מצאאיו.

**ייצוג כמערך**: עץ בינארי שלם מתאים בדיוק למערך. צומת באינדקס \(i\) (אינדקס 0):
\[
\text{parent}(i) = \lfloor(i-1)/2\rfloor, \quad
\text{left}(i) = 2i+1, \quad
\text{right}(i) = 2i+2
\]

דוגמה: min-heap `[2, 5, 3, 8, 7, 9]` מייצג את העץ:

```
       2
      / \
     5   3
    / \ /
   8  7 9
```

**מורכבויות זמן**:

| פעולה | זמן |
|-------|-----|
| heappush (הכנסה) | \(O(\log n)\) |
| heappop (הוצאת מינימום) | \(O(\log n)\) |
| heapify (בניית heap מרשימה) | \(O(n)\) |
| top-k מתוך n | \(O(n \log k)\) |

**heapq בפייתון**: ספריית heapq מימשה min-heap. היא עובדת ישירות על רשימות רגילות, ואינה מחלקה נפרדת.

```python
import heapq

h = []
heapq.heappush(h, 5)
heapq.heappush(h, 2)
heapq.heappush(h, 8)
print(heapq.heappop(h))   # 2 תמיד
```

**nlargest ו-nsmallest**: פייתון מציעה פונקציות נוחות:

```python
heapq.nlargest(3, [5, 1, 8, 3, 9, 2, 7])   # [9, 8, 7]
heapq.nsmallest(3, [5, 1, 8, 3, 9, 2, 7])  # [1, 2, 3]
```

פנימית הן משתמשות ב-heap בגודל k ולא ממיינות את כל הרשימה.

## דוגמה מחושבת

**בעיה**: מצא את 3 הגדולים ברשימה `[5, 1, 8, 3, 9, 2, 7]`.

**גישה ידנית עם min-heap בגודל 3**:

1. אתחול: h = []
2. `push 5` → h = [5]
3. `push 1` → h = [1, 5]
4. `push 8` → h = [1, 5, 8] (heap מלא)
5. `3 < h[0]=1`? לא. דלג.
6. `9 > h[0]=1`? כן. `heapreplace(h, 9)` → h = [5, 9, 8]
7. `2 > h[0]=5`? לא. דלג.
8. `7 > h[0]=5`? כן. `heapreplace(h, 7)` → h = [7, 9, 8]

תוצאה: h = [7, 9, 8] = שלושת הגדולים. \(\checkmark\)

**כמה צעדים?** עברנו על 7 מספרים (n=7), כל heapreplace לוקח \(O(\log 3)\). סך הכל \(O(7 \cdot \log 3) \approx O(n \log k)\).

**קוד פייתון**:

```python
import heapq

def top_k(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)
    return sorted(heap, reverse=True)

print(top_k([5, 1, 8, 3, 9, 2, 7], 3))  # [9, 8, 7]
```

## המקרה שמפיל את האינטואיציה

**כשk גדול מאוד**: אם k = n/2, ה-heap שומר חצי מהרשימה. כל heapreplace לוקח \(O(\log(n/2)) = O(\log n)\) ממש כמו מיון. במקרה זה עדיף פשוט למיין עם `sorted()` שהוא קצר יותר לכתיבה ולא איטי יותר.

**כשn קטן**: על רשימות קצרות (נניח פחות מ-500 מספרים), מיון עם `sorted()` מהיר מספיק ופשוט יותר לקריאה. heapq מתאים לn גדול מאוד.

**כשנתונים מגיעים ב-stream**: heap זורח כשנתונים מגיעים אחד אחד ואי אפשר לטעון הכל לזכרון. מיון מחייב שכל הנתונים יהיו בזכרון בו-זמנית.

## טעויות נפוצות

**1. שכחת ש-heapq היא min-heap בלבד.** פייתון אין לה max-heap מובנה. לmmax-heap צריך להפוך את הסימן:

```python
max_heap = []
heapq.heappush(max_heap, -5)   # שמור -5
heapq.heappush(max_heap, -9)   # שמור -9
print(-heapq.heappop(max_heap))  # 9 (הגדול)
```

**2. בלבול בין heap לבין sorted list.** heap אינה ממיינת את כל האלמנטים. `h[1]` אינה בהכרח השניה הקטנה. הדבר היחיד המובטח הוא `h[0]` = המינימום.

**3. שימוש ב-sort לבעיות top-k.** `sorted(lst)[-k:]` לוקח \(O(n \log n)\). כשn גדול מאוד ו-k קטן, ה-heap חוסך זמן ומשמעותי.

**4. שכחת לבדוק גודל heap.** בגישת ה-heap בגודל k, יש לוודא שמוציאים מהערימה כשהיא עוברת גודל k, לא לפני.

## מתי זה לא משנה

**כשn קטן (n < 1000)**: הבדל בין \(O(n \log k)\) ל-\(O(n \log n)\) אינו מורגש. קוד עם `sorted()` קצר יותר ועדיף.

**כשk = 1**: מחפשים פשוט את המקסימום/מינימום. `max(lst)` הוא \(O(n)\) ופשוט בהרבה.

**בראיון**: אם מראיין שואל "כיצד תמצא top-k?", התשובה היא heap. אם שואל "כיצד תמצא את המקסימום?", התשובה היא לולאה פשוטה, לא heap.

## חיבור

היחידה הזו היא ציר מרכזי בבלוק M1 של מבני נתונים ואלגוריתמים. heap מופיע שוב ב-Dijkstra (קצרות דרכים), ב-Prim (עצי פרישה), וב-merge k sorted lists.

הבעיה "k הגדולים" חוזרת בצורות רבות בראיונות: k השכנים הקרובים ביותר, k המניות עם הרווח הגבוה ביותר, k ה-queries הפופולריים ביותר. פתרון heap-k הוא פתרון template שכדאי לזכור בעל פה.
