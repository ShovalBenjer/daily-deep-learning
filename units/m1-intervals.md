# קטעים (Intervals)
בבעיות קטעים יש בדיוק שתי פעולות: מיון פעם אחת, מעבר לינארי פעם אחת.

## מה תדע בסוף
תזהה בעיות בסגנון "מזג קטעים" או "בדוק חפיפה", תממש מיזוג קטעים ב-Python בעזרת מיון ומעבר אחד, ותסביר את תנאי החפיפה אחרי מיון.

## האינטואיציה
דמיין אפליקציית לוח שנה. כל פגישה היא זוג \([start, end]\). אם רוצים לדעת אילו פגישות מתנגשות, ממיינים לפי שעת התחלה ומטיילים בסדר. אחרי המיון, כל פגישה חדשה ממורחת רק מול האחרונה שנראתה, כי שתי פגישות כלשהן שמתחילות עוד יותר מוקדם כבר מוזגו לתוכה. האנלוגיה מחזיקה כל הדרך: "האם הפגישה הבאה מתחילה לפני שהנוכחית נגמרת?" הוא כל מה שצריך לבדוק.

## ההגדרות המדויקות
**Interval, קטע**: זוג מספרים שלמים \([start, end]\) עם \(start \le end\) המייצג טווח סגור על ציר מספרים.

**חפיפה (Overlap)**: שני קטעים \([a, b]\) ו-\([c, d]\) חופפים אם ורק אם:
\[\max(a, c) \le \min(b, d)\]
מסתדר לצורה פשוטה יותר: הם **אינם** חופפים אם ורק אם \(b < c\) (הראשון נגמר לפני שהשני מתחיל) או \(d < a\) (השני נגמר לפני שהראשון מתחיל).

**אחרי מיון לפי \(start\)**: נניח \(a \le c\). אז החפיפה מצטמצמת לתנאי אחד בלבד:
\[c \le b\]

**מיזוג (Merge)**: אם \([a,b]\) ו-\([c,d]\) חופפים (ו-\(a \le c\)), הקטע הממוזג הוא:
\[[a,\ \max(b, d)]\]

שימי לב שמקצר ה-end הוא `max`, לא `end`. קטע שבלוע בתוך אחר גדול ממנו חייב לשמור על ה-end של הגדול.

## דוגמה מחושבת
קלט: `[[1,3],[2,6],[8,10],[15,18]]`

**שלב 1: מיון לפי start.**
המערך כבר ממוין.

**שלב 2: מעבר.**
```
merged = [[1,3]]
---
[2,6]:  2 <= 3  ->  חפיפה! merged[-1] = [1, max(3,6)] = [1,6]
[8,10]: 8 > 6   ->  אין חפיפה. append -> merged = [[1,6],[8,10]]
[15,18]:15 > 10 ->  אין חפיפה. append -> merged = [[1,6],[8,10],[15,18]]
```

קוד Python:
```python
def merge(intervals: list[list[int]]) -> list[list[int]]:
    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]
    for start, end in intervals[1:]:
        if start <= merged[-1][1]:          # חפיפה
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged
```

סיבוכיות: \(O(n \log n)\) מהמיון, \(O(n)\) מהמעבר, \(O(n)\) זיכרון לרשימת הפלט.

## המקרה שמפיל את האינטואיציה
**קטע שבולע אחרים (Containment):** `[[1,10],[2,3],[4,5]]`

```
merged = [[1,10]]
[2,3]: 2 <= 10 -> חפיפה!
  merged[-1][1] = end = 3   # BUG: קיצרנו [1,10] ל-[1,3]!
  merged[-1][1] = max(10,3) # CORRECT: נשאר [1,10]
[4,5]: 4 <= 10 -> חפיפה!
  same issue if using `= end`
```

השגיאה: `merged[-1][1] = end` במקום `max(...)`. קטע שבלוע בתוך קטע גדול יותר מצמצם בטעות את ה-end לערך קטן. הכלל: **תמיד `max`**.

## טעויות נפוצות
**1. שכחת מיון.** ללא מיון, `[3,5]` יגיע לפני `[1,4]` ונחמיץ את החפיפה ביניהם. המיון הוא לא אופציה.

**2. `merged[-1][1] = end` במקום `max`.** כפי שנראה בדוגמה למעלה, קטע בלוע יצמצם את ה-end הנוכחי. השגיאה הזו עוברת בבדיקות בסיסיות ונפלת על test case עם containment.

**3. אינדקס שגוי: `merged[-1][0]` במקום `merged[-1][1]`.** בעת השוואה לוקחים את ה-end של הקטע האחרון שנמזג, לא את ה-start שלו.

**4. "Meeting Rooms": בדיקה אם יש חפיפה כלשהי.**
```python
# WRONG: לא ממיין לפני הבדיקה
for i in range(len(intervals)-1):
    if intervals[i][1] > intervals[i+1][0]:   # ...

# CORRECT:
intervals.sort(key=lambda x: x[0])
for i in range(1, len(intervals)):
    if intervals[i][0] < intervals[i-1][1]:
        return False   # חפיפה נמצאה, לא ניתן להשתתף בכל
return True
```

**5. גבול פתוח מול סגור.** לפגישות [1,2] ו-[2,3]: האם הן חופפות? תלוי בהגדרה (קצוות סגורים = כן, פתוחים = לא). קראי את ה-constraints של השאלה.

## מתי זה לא משנה
**שני קטעים בלבד:** אין צורך במיון. `max(a,c) <= min(b,d)` עובד ישירות ב-O(1).

**קלט ממוין ולא-חופף:** ניתן להוסיף קטע חדש ב-O(log n) עם binary search על ה-start, בלי לרוץ מחדש על הכל.

**n קטן (n < 20 בקוד production):** לולאה מקוננת O(n²) קריאה יותר מאשר sort + scan, ולמעשה מהירה יותר בגלל overhead קטן.

**ראיונות:** השאלה "Merge Intervals" בדרך כלל מצפה ל-O(n log n). אם תוצאת O(n²) עם הסבר ברור תוצג ראשונה, רוב המראיינים יקבלו את זה כנקודת פתיחה לדיון.

## חיבור

בתוך M1, קטעים הם ייצוג נוסף לאותו רעיון שנראה ב-sliding window: חלון על ציר שמתרחב ומתכווץ. ההבדל הוא שב-intervals הקצוות נתונים מראש; ב-sliding window אנחנו עצמנו מחליטים מה ה-window.

הפנים הבאות של הרעיון:
- **Meeting Rooms II (LeetCode 253):** כמה חדרי ישיבות דרושים בו-זמנית? מוסיפים min-heap שעוקב אחרי ה-end של כל חדר פעיל.
- **Non-overlapping Intervals (LeetCode 435):** הסרה גרידית מינימלית. כאן ממיינים לפי **end** (לא start) כדי לשמור על המרב.
- **Insert Interval (LeetCode 57):** הכנסה לרשימה ממוינת ולא-חופפת: שלושה שלבים (לפני, מיזוג, אחרי).

ב-M2 (SQL), בעיות gaps-and-islands הן בדיוק אותה בעיה: רצפים רצופים של תאריכים הם "קטעים ממוזגים", והפערים ביניהם הם ה-gaps.
