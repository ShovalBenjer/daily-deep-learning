# רשימה מקושרת
שלושה מצביעים בלבד מספיקים כדי להפוך שרשרת שלמה, ולהבין את כל מבני המצביעים שיבואו אחר כך.

## מה תדע בסוף
תוכל לממש רשימה מקושרת חד-כיוונית בפייתון, לחצות אותה, להוסיף ולמחוק צמתים, ולהפוך אותה. תוכל להסביר מתי רשימה מקושרת עדיפה על מערך ומתי לא.

## האינטואיציה
דמיין שרשרת של קרונות רכבת. לכל קרון יש תוכן (המטען) ואת הקרון שמאחוריו (המצביע `next`). אין גישה ישירה לקרון ה-7. צריך לעלות על קרון 1, לעבור לקרון 2, ולמנות עד 7.

היתרון: הוספת קרון חדש לתחילת השרשרת לא מחייבת הזזה של כולם. פשוט מצביעים מהקרון החדש לקרון שהיה ראשון. זה \(O(1)\) בניגוד ל-\(O(n)\) במערך.

החיסרון: לא ניתן לקפוץ לקרון ה-7 ישירות. חייבים לחצות.

## ההגדרות המדויקות

**Node, צומת** - האבן הבסיסית. אובייקט עם שני שדות:

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

**Linked list, רשימה מקושרת** - רצף של צמתים שכל אחד מצביע לבאה. ה-`next` של הצומת האחרונה הוא `None`.

**Head, ראש** - הצומת הראשונה. זהו המשתנה היחיד שמייצג את כל הרשימה. כשמשהו צריך "לגשת לרשימה", הוא מקבל את ה-head.

**Tail, זנב** - הצומת האחרונה, שה-`next` שלה הוא `None`.

**Singly linked list, רשימה חד-כיוונית** - כל צומת מכירה רק את הבאה. זו הצורה הנפוצה בשאלות ראיונות.

**Doubly linked list, רשימה דו-כיוונית** - כל צומת מכירה גם את הקודמת (`prev`) וגם את הבאה (`next`). נדרשת למבנים כמו LRU cache שצריכים מחיקה יעילה מכל מקום.

### סיבוכיות הפעולות

| פעולה | זמן | הסבר |
|---|---|---|
| גישה לאינדקס k | \(O(n)\) | חייבים לחצות מהראש |
| הוספה לראש | \(O(1)\) | רק עדכון head |
| הוספה לזנב (ללא tail pointer) | \(O(n)\) | חייבים למצוא את הסוף |
| הכנסה לאחר צומת ידועה | \(O(1)\) | רק עדכון מצביעים |
| מחיקת ראש | \(O(1)\) | `head = head.next` |
| חיפוש ערך | \(O(n)\) | חציה מלאה |

השוואה מול `list` של פייתון (מערך דינמי):

| פעולה | list | linked list |
|---|---|---|
| גישה ל-`a[k]` | \(O(1)\) | \(O(n)\) |
| הוספה לסוף (`append`) | \(O(1)\) מופרש | \(O(1)\) עם tail pointer |
| הוספה לתחילה (`insert(0,x)`) | \(O(n)\) | \(O(1)\) |
| overhead זיכרון | נמוך | מצביע `next` לכל צומת |

### בניית רשימה בפייתון

```python
# בונים: 1 -> 2 -> 3 -> None
node3 = ListNode(3)
node2 = ListNode(2, node3)
node1 = ListNode(1, node2)
head = node1
```

### חציה

```python
def traverse(head):
    curr = head
    while curr:
        print(curr.val)
        curr = curr.next
```

### הוספה לראש

```python
def prepend(head, val):
    new_node = ListNode(val)
    new_node.next = head
    return new_node  # ה-head החדש
```

## דוגמה מחושבת

**הפיכת רשימה מקושרת** - reverse linked list. שאלת הראיון הנפוצה ביותר במבנה נתונים זה.

**קלט**: 1 -> 2 -> 3 -> None  
**פלט**: 3 -> 2 -> 1 -> None

האלגוריתם: שלושה מצביעים - `prev`, `curr`, `nxt`.

```python
def reverseList(head):
    prev = None
    curr = head
    while curr:
        nxt = curr.next   # שמור את הבאה
        curr.next = prev  # הפוך את המצביע
        prev = curr       # קדם prev
        curr = nxt        # קדם curr
    return prev           # prev הוא הראש החדש
```

**מעקב שלב-שלב** על הקלט 1 -> 2 -> 3 -> None:

**מצב התחלתי**: `prev = None`, `curr = 1`

**סיבוב 1** (`curr = 1`):
- `nxt = 2`
- `1.next = None` (1 עכשיו מצביע ל-None)
- `prev = 1`, `curr = 2`
- מצב: `None <- 1 |  2 -> 3 -> None`

**סיבוב 2** (`curr = 2`):
- `nxt = 3`
- `2.next = 1` (2 עכשיו מצביע ל-1)
- `prev = 2`, `curr = 3`
- מצב: `None <- 1 <- 2 |  3 -> None`

**סיבוב 3** (`curr = 3`):
- `nxt = None`
- `3.next = 2` (3 עכשיו מצביע ל-2)
- `prev = 3`, `curr = None`
- מצב: `None <- 1 <- 2 <- 3`

**הלולאה מסתיימת** כי `curr = None`. מחזירים `prev = 3`.

תוצאה: 3 -> 2 -> 1 -> None.

סיבוכיות: \(O(n)\) זמן, \(O(1)\) זיכרון נוסף. כל צומת מבוקרת פעם אחת בלבד.

## המקרה שמפיל את האינטואיציה

**מחיקת צומת כשיש לנו רק מצביע אליה, לא לקודמת**.

נניח שיש לנו מצביע לצומת שרוצים למחוק. האינטואיציה אומרת "נסיר אותה מהרשימה". אבל כדי לנתק צומת, מי שמצביע אליה (הצומת הקודמת) צריך לעדכן את ה-`next` שלה לבאה. ואין לנו גישה לקודמת.

**הפתרון**: העתק את הערך מהצומת הבאה לצומת הנוכחית, ומחק את הצומת הבאה:

```python
def deleteNode(node):
    # עובד רק כשהצומת אינה הזנב
    node.val = node.next.val
    node.next = node.next.next
```

לפני: ... -> `[4]` -> `[5]` -> `[6]` -> ...  
אנחנו רוצים למחוק `[5]`. מצביע שלנו: `node = [5]`.  
אחרי `node.val = node.next.val`: ... -> `[4]` -> `[6*]` -> `[6]` -> ...  
אחרי `node.next = node.next.next`: ... -> `[4]` -> `[6]` -> ...

המחיקה הצליחה, אבל על ידי שינוי תוכן הצומת, לא על ידי הסרתה ממש.

**Dummy head, ראש בובה** - pattern לפישוט מחיקות. כדי להימנע מטיפול מיוחד במחיקת ראש הרשימה, מוסיפים צומת זמנית לפניו:

```python
def removeElements(head, val):
    dummy = ListNode(0)
    dummy.next = head
    curr = dummy
    while curr.next:
        if curr.next.val == val:
            curr.next = curr.next.next  # מחיקה
        else:
            curr = curr.next
    return dummy.next
```

בלי הבובה, מחיקת הראש דורשת `if` מיוחד. עם הבובה, כל הצמתים (כולל הראש) מטופלות אחיד.

## טעויות נפוצות

1. **שכחת `nxt` לפני ההיפוך** - הטעות הנפוצה ביותר. קוד `curr.next = prev; curr = curr.next` שגוי: `curr.next` כבר `prev`, לא הצומת הבאה. הרשימה אבודה.

2. **החזרת `curr` במקום `prev`** - בסוף לולאת ההיפוך, `curr` הוא `None` (לכן הלולאה נגמרה). `prev` הוא הזנב המקורי שהפך לראש החדש.

3. **לא בודקים קלט ריק** - `head = None` הוא קלט חוקי. `curr.next` על `None` קורס. הכניסו בתחילה:
   ```python
   if not head or not head.next:
       return head
   ```

4. **Off-by-one בחיפוש הצומת ה-k** - לחציית "עד הצומת ה-k" חייבים לעצור על ה-k-1 כדי שיהיה אפשר לבצע מחיקה או הכנסה. עצירה על ה-k עצמה מונעת גישה לקודמת.

## מתי זה לא משנה

**כשצריך גישת אינדקס תכופה** - Python `list` עם `a[k]` ב-\(O(1)\) תמיד עדיפה. Linked list מאבדת את היתרון ברגע שמחפשים לפי אינדקס.

**כשהרשימה קצרה** - עבור פחות מ-100 אלמנטים, `list` מהירה יותר בפועל בשל cache locality: האלמנטים צמודים בזיכרון ומעבד מטעין אותם בבלוק אחד. Linked list פוגעת בזה.

**`collections.deque` עדיפה לתורים** - מממשת רשימה דו-כיוונית מבפנים ומאפשרת \(O(1)\) הוספה ומחיקה משני הקצוות. לא כדאי לממש linked list ידנית לצרכי תור בפייתון.

**בראיונות** - שאלות linked list בודקות יכולת מניפולציה של מצביעים, לא מבנה נתונים מעשי. אל תמירו למערך כדי לפשט: זה מחמיץ את הנקודה שהמראיין בוחן.

## חיבור

**בתוך M1**: רשימה מקושרת היא הבסיס ל-stack (ראש הרשימה הוא ה-top), ל-queue (head לפלט, tail לקלט), ול-LRU cache (רשימה דו-כיוונית + hashmap). שאלות tree traversal משתמשות ב-stack או ב-queue מבוסס רשימה מקושרת.

**דפוסים שחוזרים**: שלושת המצביעים (`prev`, `curr`, `nxt`) וה-dummy head מופיעים כמות שהם בשאלות tree ו-graph. הבנתם כאן חוסכת פיתרון מחדש.
